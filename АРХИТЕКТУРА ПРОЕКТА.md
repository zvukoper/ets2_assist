## Processes and ports
telemetry: game/plugin -> WebSocket/REST `localhost:8080`; API includes `/api/ws/delta/flat/?throttle=16` (AR tick is 16 ms) and `/api/rest/single/frame/paused`.
web_static: Python/overlay HTTP server `localhost:8082`; serves `data/`.
app_http: GUI HttpListener `localhost:8083`; CORS enabled.
app_ws: GUI WebSocketSharp `localhost:8084`; commands + track upload.
legacy: `Ets2Telemetry.exe` is disabled; `ets2-telemetry-server.dll` is not required by the current startup path.

## Data flow
map: `web_pda_map.html` -> telemetry 8080; commands/save 8084; trigger/targets 8083; static assets 8082.
hybrid: `web_ui_hybrid.html` -> telemetry 8080; commands 8084; `web_data.json` via static server.
telemetry_state: map uses `data/js/state.js`; hybrid uses `data/js/hybrid_ui_state.js`; both must update fuel/headOffset on every snapshot/delta.
static_map: `GeoJson/roads.geojson`, `GeoJson/cities.geojson`, `localized_cities/cities_sibirmap.json`, `Overlays.json`.
targets_read: `GET http://localhost:8083/custom_targets.json` -> AppDataPaths.CustomTargetsFile; never read mutable targets from static `data/`.
targets_write: `POST http://localhost:8083/update_targets` with JSON array; server wraps `{customTargets:[...]}`.
ui_visibility: GUI checks pause/focus every 500 ms; sends `show_ui_first`, `show_ui`, `hide_ui` over 8084.

## Track save contract
request: client sends `{format:"compact_v2", data, meta, mapData, customTargets, requestId}` to 8084.
commands: `save_trail`, `start_recording`, `stop_recording`, `reset_recording_origin`, `add_random_target`, `remove_random_target`, `reset_target_reached`, `show_ui_first`, `show_ui`, `hide_ui`, `play_sound`.
guards: save only after actual ETS2 pause confirmation; duplicate `requestId` must not create a second track.
response: `{status:"ok"|"error", message, requestId}`.
compact: first line metadata JSON; trail `<t>;<x>;<z>;<heading>;<speed>`; data `D;...;<headOffset>`; events `E;...`.
headOffset: six numbers; index 3 is normalized heading 0..1.

## AR (v1 web / v2 native)
ar1: `data/js/ar_hud.js` (dumb receiver, canvas). ar2: `AR/*.cs` (D3D11, `ArRenderer`), FOV from `ArBridge.FovDegrees` (AR2, 100).
ar1_fov: `ArBridge.FovDegreesAr1` (75) + `AppSettings.Ar1FovDeg`; hotkeys Ctrl+PGUP/PGDN ±1° → command `ar_fov` → `CFG.fovDeg` (AR1), `state.fovDeg` (minimap), `MapEditor2SetFov` (editor 2). FOV text drawn bottom-left in AR1 with black outline.
ar1_process: external `WebOverlay` window (`MainWindowTitle` contains "AR HUD"); AR1 button state is derived by scanning processes (2 s tick), not by a flag.
ar_feed: C# `MainForm.ArTarget.cs` is the only producer; events `ar_target`/`ar_telemetry`/`ar_pin`/`ar_fov`/`debug_show` over 8084. `StartArTargetFeed` forces `_arTruckChanged=true`, `_arTelemetryForced=true`, `_arCitiesSent=false`, `_arLastHeadSent=null`; each new WS client triggers `ForceArDataResend(reason)`.
ar_feed_rule: `_arTelemetryForced` is a STICKY request flag — incoming data must NOT clear it; only the tick clears it after a successful send. `_arTruckChanged` alone is overwritten by `ApplyPlacementJson` (WS + 1 Hz REST) before the 33 ms tick (root cause of "AR1 shows no telemetry").
ar_tick: `System.Threading.Timer` (NOT `System.Windows.Forms.Timer` — the WinForms timer did not tick at all, so NO data ever reached AR1). `StartArTickTimer`/`StopArTickTimer`/`QueueArUpdateTick`; WS/UI work marshalled with `BeginInvoke`; `Interlocked _arTickBusy` prevents overlapping 16 ms ticks (was 33 ms). Liveness line `[AR] tick alive:` in app_data every 5 s.
publish_cache: `compile.ps1` clears WebView2 profiles RECURSIVELY (the WebOverlay profile lives at `publish\data\bin\WebOverlay.exe.WebView2\EBWebView`, two levels down, ~34 MB) and verifies delivery (`data\` vs `publish\data`: MD5 for web content, sizes for the rest) plus that no `*.WebView2`/`EBWebView` folders remain. Overlay host is killed before wiping (it holds profile locks).
camera: REAL SCS 6DoF pose (`AR/ScsCameraPose.cs`), NOT heuristics: `head_cabin = head.position + head.offset.position` -> `head_vehicle = cabin.position + cabin.offset.position + rotate(cabin.offset.orientation, head_cabin)` -> `head_world = truck.world.position + rotate(truck.world.orientation, head_vehicle)`; same hierarchy for orientation. `ScsCameraPose.Rotate` = Roll(Z) -> Pitch(X) -> Heading(Y); angles are TURN FRACTIONS (x2pi). Base head looks along local -Z (SCS: X right, Y up, Z back). Basis Forward/Right/Up is Gram-Schmidt orthonormalized in `TryCreate`. `ArGameState.CamX/Y/Z` = EYE world position; `CameraForward/Right/Up` + `CameraPoseValid`; `Yaw*/Pitch*` are DIAGNOSTICS ONLY and never used in projection. FORBIDDEN in AR runtime: EyeHeight, PitchCompensation, separate roll hack, `u` mirroring, screen smoothing, prediction, nearest-city height, wheel-plane camera height.
projection: ONE path world->screen: `world - camera.position` -> dots with CameraForward/Right/Up -> pinhole `f = W/2 / tan(FOV/2)` (same f for X and Y). `AR/CabinArProjection.Project` + `ar_hud.js projectPoint` both implement exactly this; no post-projection add-ons.
ar_payload: `ar_telemetry` carries the finished pose `camera{position,forward,right,up,fovDeg,valid}`; legacy `placement`/`head` are status/diagnostics only. `PublishArV2Snapshot` publishes only when `_arCameraPoseValid`.
hotkeys_game_vs_editor: `CTRL+X` and `SHIFT+CTRL+X` both create a TEMPORARY (virtual) marker only — AR1 `ar_pin` + minimap `ar_pin_map`. No map editor is opened or focused; such a point cannot be saved. Map editor 1 button REMOVED.
point_to_ar: creating a point in Map Editor 2 (`map2-create-point`) also places the AR1 `ar_pin` and the minimap pin at those exact coordinates.
view_cone: half-angle = FOV/2 (min 5°) — NOT the pitch; length = ground distance under crosshair, unified formula `eyeH/|tan(pitch)|`, `eyeH=1.5` (`MapEditorForm.EyeHeightActrosM`), clamp 1500 m (`ViewConeMaxDistM`); pitch is a TURN FRACTION (×2π). Used by `map_draw.js`, `map_editor2/index.html`, legacy `MapEditorVectorRenderer.DrawCone`. REMOVED from AR1 (`ar_hud.js`) by user decision — in AR1 the cone equals our POV.
horizon: WORLD horizon (both AR1 `drawWorldHorizon` and `ArRenderer.DrawWorldHorizon`): horizon = world rays ⟂ world Up=(0,1,0); `v = cy + f*(Forward.Y + Right.Y*x)/Up.Y`, degenerate case = vertical line. Drawn before markers. Old `horizonScreenLine`/`ComputeHorizonLine` (composite pitch + roll) DELETED — it did not hold the horizon when the head moved up/down.
above_horizon: `dirY=sin(pitch) >= -1e-6` → distance NaN, no distance label, grey diagonal micro-cross (`drawDiagCross` / `ArRenderer.DrawDiagCross`).
debug_show: `data/js/debug_show.js` — the single `debugShow(bool)` method connected FIRST in `<head>` of EVERY data/*.html page (13 incl. `map_editor2/index.html`). true = ignore visibility logic and force content visible (CSS `.debug-show-force`, classList/style freeze, MutationObserver, 500 ms re-assert, inline styles saved/restored); false = restore original logic. Inputs: `window.debugShow(bool)`, `?debugshow=1`, WS `{command:'debug_show',enabled}`; UI checkbox `chkWebDebug` + `ArBridge.DebugShow`.
map_editor1: REMOVED from UI (button + `btnMapEditor` field deleted; button grid anchor is now `btnStart`). `MapEditorForm` stays in code as legacy — its statics are used by the overrides pipeline.
point_visibility: `PointData.ShowInAr` / `ShowOnMap` (default true) ↔ JSON `showInAr` / `showOnMap`; read with `MapEditorForm.ReadBoolToken` (internal; accepts bool/int/float/"true"/0/1); minimap is dumb → `showOnMap` folded into `hidden`; AR channel filters by `ShowInAr`. Strict: without both flags a point is hidden everywhere.

## Rules
version: `MAJOR.MINOR.PATCH-DESCRIPTION-YYYY.MM.DD-HHmm`; every functional change increments PATCH; synchronize BuildInfo.cs, project VersionPrefix, web badges, `data/web_runtime_manifest.json`, `data/ets2_assist_build.txt`, and playback build log.
source_of_truth: edit root `data/`; publish is generated output; do not use publish as the only source.
release: `dotnet publish -c Release`; verify EXE and `publish/data` after publishing.
cache: preserve stable overlay URLs; invalidate changed local assets through existing cache/version mechanism.
compatibility: preserve ports, REST paths, WebSocket commands and compact track format unless plan explicitly changes a contract.
logging: use existing Logger/AppendLog; log requestId and data-flow failures; do not silently hide new errors.
window: save/restore bounds with `Screen.DeviceName`; clamp to current working area if monitor is absent.

# Проект ETS2 Assist — архитектурная документация

## 1. Общий алгоритм работы приложения

ETS2 Assist — это система для отображения телеметрии Euro Truck Simulator 2 на интерактивной карте, записи треков движения, управления случайными заданиями (целями) и воспроизведения треков.

**Поток данных:**
1. Игра ETS2 передаёт телеметрию напрямую через TruckTel на WebSocket 8080; целевая архитектура — собственный ets2_assist_plugin.dll с тем же API. Старый ets2-telemetry-server больше не запускается.
2. Desktop-приложение (GUI) запускает:
   - WebSocket-сервер для приёма телеметрии (порт 8080) – от TruckTel.
   - HTTP-сервер для статики (порт 8082) – отдаёт HTML/CSS/JS/GeoJSON.
   - HTTP-сервер для триггера и списка треков (порт 8083).
   - WebSocket-сервер для команд и сохранения треков (порт 8084).
3. Веб-страница `web_pda_map.html` подключается к WebSocket телеметрии (порт 8080) и к командному WebSocket (8084). Отображает карту, трек, цели, POI, города, дороги.
4. Веб-страница `web_ui_hybrid.html` подключается к телеметрии (8080) и к командному WebSocket (8084). Показывает приборную панель (скорость, топливо, отдых, задание и т.д.).
5. Управление видимостью UI осуществляется через WebSocket-команды `show_ui_first`, `show_ui`, `hide_ui` от приложения в зависимости от состояния паузы и фокуса окна игры.
6. При нажатии хоткея `Shift+Ctrl+S` GUI создаёт `save_trail.trigger` только если ETS2 фактически находится на паузе; сохранение вне паузы блокируется.
7. Карта периодически проверяет наличие этого файла через HTTP-запрос на порт 8083. Если файл найден, карта отправляет собранный трек через WebSocket на порт 8084.
8. GUI сохраняет трек в папке `data/saved_tracks/` в виде `.track` (компактный), `.meta.json`, `.map.json` и генерирует standalone HTML-плеер.
9. Плеер открывается автоматически, список треков отображается в GUI и на странице `trail_player.html`.

**Управление случайными целями:**
- Кнопка в GUI «Случайная цель» отправляет команду `add_random_target` на карту.
- Карта генерирует цель на дороге в радиусе 2 км, не дальше 10 м от дороги и не дальше 50 м от POI, сохраняет её в `custom_targets.json` через `POST /update_targets`.
- При достижении цели (<50 м) карта отправляет `target_reached` на сервер.
- GUI показывает диалог «Завершить задание?». При согласии начисляет 3000 денег и 150 опыта через `ets2c.exe`, удаляет цель.
- При отказе сбрасывается флаг, и при повторном приближении диалог появляется снова.

## 2. Модули и их описание

### 2.1. Desktop-приложение (C# WinForms)

**Главный класс:** `MainForm` (partial, разбит на несколько файлов).

**Основные файлы:**
- `MainForm.cs` – инициализация UI, серверов, горячих клавиш, обработчики системных событий.
- `QuestsManager.cs` – логика случайных целей (генерация, триггеры, награды).
- `WebUIManager.cs` – управление видимостью веб-контента (проверка паузы, фокуса, отправка команд `show_ui`/`hide_ui`).
- `TrailSaver.cs` – генерация HTML-плеера трека, сохранение треков.
- `SplashForm.cs` – заставка с логотипом при запуске (плавное появление/исчезновение).
- `Program.cs` – точка входа, обработка исключений, показ сплеш-экрана.

**Ключевые методы:**
- `StartSystemAsync()` – запускает локальные HTTP/WebSocket серверы приложения, процессы и веб-оверлей; отдельный Ets2Telemetry.exe не запускается.
- `StopSystem()` – останавливает все серверы и процессы.
- `ProcessTriggerRequest()` – обработчик HTTP-запросов (триггер, список треков, обновление целей).
- `TrailBehavior` – WebSocket-поведение для порта 8084 (приём треков, команд, звуков).
- `SendCommandToMap()` – отправка команды (например, `show_ui`, `add_random_target`) на все подключённые веб-клиенты через WebSocket 8084.
- `StartPauseCheck()` – запускает таймер проверки паузы и фокуса игры.

**Управление видимостью UI:**
- `WebUIManager.cs` проверяет каждые 500 мс состояние паузы (`/api/ets2/telemetry`) и фокус окна игры.
- При первом появлении отправляет `show_ui_first` (анимация увеличения 2 с).
- При последующих переключениях – `show_ui` (быстрый fade-in 150 мс) или `hide_ui` (быстрый fade-out 150 мс).

**Сохранение трека:**
- `SaveTrailFromWebSocket()` получает компактные данные и метаданные, сохраняет `.track`, `.meta.json`, `.map.json`, генерирует HTML-плеер через `GenerateTrailHtml()`.

### 2.2. Веб-карта (`web_pda_map.html`)

**Назначение:** отображение карты, телеметрии, сбор трека, управление целями.

**Структура JS-модулей (разбиты на файлы в `data/js/`):**
- `config.js` – константы (ZOOM_MIN, MAX_SPEED, TRAIL_INTERVAL, калибровка pitch/roll).
- `state.js` – глобальное состояние (позиция, цели, города, дороги, POI, трек, данные).
- `greedy.js` – алгоритм жадной расстановки меток и создание HTML-меток.
- `websocket.js` – WebSocket-клиенты: телеметрия (TruckTel, порт 8080) и командный/сохранения (порт 8084). Обработка команд `add_random_target`, `remove_random_target`, `show_ui_*`, `hide_ui`.
- `trail.js` – обновление шлейфа, сбор точек с интервалами, вычисление событий (парковка, урон, остановки), отслеживание достижения цели.
- `save.js` – генерация компактного трека, отправка на сервер, сброс трека.
- `targets.js` – загрузка/сохранение `custom_targets.json`, генерация случайной цели (поиск точки на дороге с учётом расстояния до POI и дороги).
- `map_helpers.js`, `map_pitchroll.js`, `map_draw.js`, `map_controls.js` – отрисовка карты, управление зумом/перетаскиванием, индикаторы pitch/roll.
- `ui.js` – обработчики кнопок (навигация, цели, зум, буфер обмена).
- `init.js` – загрузка данных (города, дороги, POI), инициализация WebSocket-соединений, периодическая проверка триггера, запуск анимаций.

**Ключевые функции:**
- `loadData()` – загружает города из `localized_cities/`, дороги из `GeoJson/roads.geojson`, POI из `Overlays.json` (рекурсивный обход).
- `drawMinimap()` – полная отрисовка карты: фон, сетка, дороги, города, POI, шлейф, цели, события, грузовик, метки.
- `updateTrail()` – добавляет точки в шлейф и `dataPoints` с интервалами, записывает pitch/roll, lights, gameTime, localScale, steering, throttle, brake, odometer, headOffset.
- `generateRandomTarget()` – ищет точку на дороге с учётом ограничений (≤10 м от дороги, ≤50 м от POI, в радиусе 2 км от грузовика). При неудаче использует запасные стратегии.
- `saveTargetsToFile()` – сохраняет цели в `custom_targets.json` через `POST /update_targets`.

**Анимации:**
- Первый показ: увеличение с 0.45 до 1 за 2 с (ease-in-out).
- Быстрый показ/скрытие: fade за 150 мс.

### 2.3. Гибридный интерфейс (`web_ui_hybrid.html`)

**Назначение:** приборная панель (скорость, топливо, отдых, задание, дальность, индикаторы).

**Структура JS-модулей (префикс `hybrid_ui_`):**
- `hybrid_ui_config.js` – константы (интервалы, порты).
- `hybrid_ui_state.js` – состояние (значения датчиков, язык).
- `hybrid_ui_dom.js` – ссылки на DOM-элементы.
- `hybrid_ui_http.js` – опрос `web_data.json` (обновление данных, без показа UI).
- `hybrid_ui_websocket.js` – WebSocket для телеметрии (порт 8080) и командный (порт 8084). Обработка `show_ui_*`, `hide_ui`.
- `hybrid_ui_update.js` – обновление UI: скорость, топливо, отдых, задание, индикаторы двигателя/парковки/прицепа/света, полоса чувствительности Arduino.
- `hybrid_ui_init.js` – загрузка языка, инициализация опроса и WebSocket-соединений.

**Особенности:**
- Появляется/скрывается синхронно с картой по тем же командам.
- Использует данные из `web_data.json` (формируется скриптом PowerShell) и WebSocket для скорости.
- Индикаторы: двигатель, парковка, прицеп, свет (ближний/дальний), полоса чувствительности.

---

### 2.4. HTML-плеер трека (`track_*.html`)

**Генерируется** методом `GenerateTrailHtml` в `TrailSaver.cs`.

**Особенности:**
- Полный standalone HTML со встроенными данными трека и карты.
- Использует **3D-индикатор грузовика** на основе CSS-трансформаций (вращение по heading, pitch, roll) вместо треугольника.
- Отображает города, дороги, цели (active/inactive), события, шлейф, данные топлива/повреждений.
- Панель pitch/roll с числовыми значениями, экстремумами и кнопкой сброса.
- Управление воспроизведением: play/pause, шаг, события, скорость, ползунок времени.
- Карта поддерживает зум и перетаскивание (инвертированное), плавное слежение за грузовиком.

**Интерполяция:** между точками шлейфа (по времени) для плавного движения.

## 3. Взаимодействие через WebSocket и HTTP

| Порт | Назначение | Клиент | Сервер |
|------|------------|--------|--------|
| 8080 | Телеметрия TruckTel | `web_pda_map.html`, `web_ui_hybrid.html` | Плагин игры (ets2-telemetry-server) |
| 8084 | Команды и сохранение треков | `web_pda_map.html`, `web_ui_hybrid.html` | GUI (WebSocket-сервер `TrailBehavior`) |
| 8083 | HTTP-запросы (триггер, список треков, обновление целей) | `web_pda_map.html` | GUI (HttpListener) |
| 8082 | Статика (HTML, CSS, JS, GeoJSON) | Браузер | Python HTTP-сервер |

**Команды WebSocket (порт 8084) от сервера к клиенту:**
- `show_ui_first` – первое появление UI с анимацией увеличения.
- `show_ui` – быстрое появление (fade-in 150 мс).
- `hide_ui` – быстрое скрытие (fade-out 150 мс).
- `add_random_target` – создать случайную цель.
- `remove_random_target` – удалить случайную цель.
- `reset_target_reached` – сбросить флаг достижения цели (для повторного триггера).

**Команды от клиента к серверу:**
- `target_reached` – цель достигнута (с координатами).
- `target_created` – цель создана (с координатами, для синхронизации состояния).
- `play_sound` – воспроизвести звук (тип: `success`, `icon`).

**HTTP-запросы:**
- `GET /check_trigger?file=save_trail.trigger` – проверка существования файла.
- `GET /delete_trigger?file=save_trail.trigger` – удаление файла.
- `GET /list_tracks` – список сохранённых треков.
- `GET /get_track/{filename}` – получить JSON трека.
- `POST /update_targets` – обновить `custom_targets.json` (принимает массив целей).

## 4. Ключевые константы и параметры

| Имя | Значение | Описание |
|-----|----------|----------|
| `TRAIL_INTERVAL` | 3 м | Минимальное расстояние между точками шлейфа |
| `DATA_INTERVAL` | 25 м | Интервал для записи данных (топливо, урон, pitch/roll) |
| `NEARBY_CITIES_COUNT` | 4 | Количество ближайших городов для отображения |
| `MAX_SPEED_KMH` | 115 | Максимальная скорость для масштабирования |
| `LABEL_PADDING` | -5 | Плотность расстановки меток (greedy placement) |
| `ZOOM_MIN`/`ZOOM_MAX` | 0.5 / 4.8 | Минимальный и максимальный зум карты |
| `PITCH_SCALE` | 360 | Коэффициент преобразования сырого pitch в градусы (по документации TruckTel) |
| `ROLL_SCALE` | 360 | Коэффициент преобразования сырого roll в градусы |
| `RAW_TO_DEGREES` | 360/283 | Альтернативный коэффициент (используется в плеере, если данные не в единицах TruckTel) |

## 5. Важные замечания для доработок

- **Звуки** передаются через WebSocket (`play_sound`), чтобы обойти ограничения автовоспроизведения в браузере. Звуки в GUI через `SystemSounds`.
- **Статические ресурсы** хранятся в коммитимой корневой папке `data` и копируются в `publish\data` при публикации. Пользовательские данные хранятся в `%LOCALAPPDATA%\ETS2_Assist`.
- **Треки сохраняются** в `%LOCALAPPDATA%\ETS2_Assist\saved_tracks` с файлами: `.track` (компактный), `.meta.json`, `.map.json`, `.html` (плеер).
- **Плеер** самодостаточен (все данные встроены в JavaScript), не требует внешних ресурсов кроме CSS.
- **Данные телеметрии** из TruckTel: `truck.world.placement` (x, y, z, rawHeading, pitch, roll), `truck.speed`, `truck.fuel`, `truck.wear`, `truck.light`, `game.time`, `local.scale`, `truck.effective.*`, `truck.odometer`, `truck.head.offset`.
- **Износ (wear)** суммируется как сумма `engine`, `transmission`, `cabin`, `chassis`, `wheels` и сохраняется как «повреждения».
- **Pitch и roll** сохраняются в градусах (по документации TruckTel: pitch = raw * 360, roll = raw * 360). В плеере для обратной совместимости используется коэффициент `360/283`.
- **Управление видимостью UI** основано на состоянии паузы (`game.paused`) и фокусе окна игры (процесс `eurotrucks2.exe`). Проверка каждые 500 мс.
- **Случайные цели** генерируются с учётом ограничений: ≤10 м от дороги, ≤50 м от POI, в радиусе 2 км. При невозможности – запасные стратегии.
- **Награды** за цели начисляются через `ets2c.exe` (команды `-moneygive 3000` и `-xpgive 150`).
- **Кеширование браузера** обходится через параметр `?v=число` в URL ресурсов (увеличивать при изменениях).

## 6. Расшифровка ключевых полей в JSON трека (компактный формат)

**Метаданные (первая строка):**
```json
{
  "version": 2,
  "title": "Название трека",
  "description": "Описание",
  "startTime": "ISO-время старта",
  "finishTime": "ISO-время финиша",
  "durationMs": 12345,
  "trailInterval": 3,
  "dataInterval": 25,
  "minSpeed": 0,
  "maxSpeed": 115,
  "totalDistance": 123.45,
  "eventTypes": { "stop": 1, "service": 2, ... }
}
```

### Строки данных:

    Точки шлейфа: <t>;<x>;<z>;<heading>;<speed>

    Точки данных (D): D;<t>;<x>;<z>;<heading>;<fuel>;<damage>;<pitch>;<roll>;<lights>;<gameTime>;<localScale>;<steering>;<throttle>;<brake>;<odometer>;<headOffset>

    События (E): E;<t>;<x>;<z>;<typeCode>;<label>;<color>;<subtext>

### Поля данных:

    lights – JSON-объект с состоянием света (aux, beacon, beamHigh, beamLow, brake, leftBlinker, rightBlinker, parking, reverse).

    gameTime – игровое время в минутах с начала эпохи.

    localScale – масштаб карты (для пересчёта игровых расстояний).

    steering, throttle, brake – значения управления (effective).

    odometer – одометр в км.

    headOffset – массив из 6 чисел (placement головы), где 4-й элемент – heading (0..1).

### mapData (сохраняется отдельно в .map.json):
json

{
  "cities": [ { "x": num, "z": num, "name": "City" } ],
  "roads": [ { "x1": num, "z1": num, "x2": num, "z2": num, "roadType": "string" } ],
  "customTargets": [ { "x": num, "y": num, "z": num, "name": "Target", "active": bool, "color": "string", "isRandom": bool } ]
}

## 8. Миграция телеметрии / native plugin

- Старый `Ets2Telemetry.exe` отключён и больше не требуется.
- `ets2-telemetry-server.dll` больше не является обязательным плагином.
- На переходном этапе допускается `trucktel.dll` + `ets2_assist_input.dll`.
- Целевой набор: один `ets2_assist_plugin.dll`, который объединит прямую SCS telemetry, WebSocket/REST API и semantic input.
- Транспорт телеметрии сохраняется совместимым с текущей картой: `ws://localhost:8080/api/ws/delta/flat/?throttle=50`.
- Пауза читается через `GET /api/rest/single/frame/paused`.
- После достижения случайной цели приложение больше не выполняет автоматический UNPAUSE.

## 9. Запись треков

Сохранение через WebSocket 8084 теперь использует `requestId`. Сервер возвращает этот идентификатор в `status=ok/error`, а клиент держит один постоянный обработчик входящих сообщений. Это исключает гонку между `send()` и установкой временного listener и позволяет безопасно игнорировать бинарные/некорректные сообщения.

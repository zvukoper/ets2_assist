# Проект ETS2 Assist — архитектурная документация

## 1. Общий алгоритм работы приложения

ETS2 Assist — это система для отображения телеметрии Euro Truck Simulator 2 на интерактивной карте, записи треков движения и их последующего воспроизведения.

**Поток данных:**
1. Игра ETS2 через плагины (ets2-telemetry-server + trucktel) отправляет телеметрию в WebSocket на порту 8080.
2. Desktop-приложение (GUI) запускает WebSocket-сервер для приёма телеметрии (порт 8080), HTTP-сервер для обслуживания статики (порт 8082) и WebSocket-сервер для сохранения треков (порт 8084).
3. Веб-страница `web_pda_map.html` подключается к WebSocket телеметрии (порт 8080) для получения данных о положении грузовика и рисует карту.
4. При нажатии хоткея `Shift+Ctrl+S` (на паузе) GUI создаёт файл-флаг `save_trail.trigger`.
5. Карта периодически проверяет наличие этого файла через HTTP-запрос на порт 8083. Если файл найден, карта отправляет собранный трек через WebSocket на порт 8084.
6. GUI сохраняет трек в виде JSON и генерирует standalone HTML-плеер в папке `data/saved_tracks/`.
7. Плеер открывается автоматически, а список треков отображается в GUI и на странице `trail_player.html`.

## 2. Модули и их описание

### 2.1. Desktop-приложение (C# WinForms)

**Главный класс:** `MainForm` (файл `MainForm.cs`)

**Задачи:** управление жизненным циклом системы, запуск серверов, обработка хоткеев, сохранение треков, отображение списка треков.

**Ключевые методы:**
- `InitializeComponents()` – создание UI (кнопки, лог, список треков, индикаторы).
- `StartSystemAsync()` – запускает плагины, телеметрию, HTTP-сервер 8082, WebSocket-сервер 8084, WebSocket-сервер для телеметрии (порт 8080).
- `StopSystem()` – останавливает все серверы и процессы.
- `TriggerTrailSave()` – создаёт файл `save_trail.trigger` в папке `data`.
- `SaveTrailFromWebSocket(JObject data)` – сохраняет полученный JSON-трек в файл, генерирует HTML и вызывает `RefreshTrackList()`.
- `RefreshTrackList()` – сканирует папку `saved_tracks` и обновляет список в `listTracks`.
- `OpenSelectedTrack()` – открывает выбранный HTML-файл через браузер.
- `GenerateTrailHtml(JObject data)` – генерирует полноценный standalone HTML-плеер для трека.
- `GenerateTrailPlayerHtml()` – генерирует страницу-обёртку для просмотра списка треков.

**Ключевые поля:**
- `_wsSaveServer` – экземпляр WebSocket-сервера (порт 8084) для приёма треков.
- `_triggerListener` – HTTP-сервер (порт 8083) для проверки/удаления триггер-файла.
- `listTracks` – ListBox для отображения списка треков.
- `logConsole` – RichTextBox для логов.

---

#### 2.1.1. WebSocket-сервер для сохранения треков (порт 8084)

**Класс:** `TrailBehavior` (внутри `MainForm`)

**Назначение:** принимает JSON-данные трека от веб-карты и сохраняет их через `SaveTrailFromWebSocket`.

**Методы:**
- `OnOpen()` – логирует подключение клиента.
- `OnMessage(MessageEventArgs e)` – обрабатывает входящие сообщения:
  - Если сообщение содержит команду `play_sound`, вызывает `_playSoundAction(soundType)`.
  - Иначе парсит JSON как трек и вызывает `_onTrail(data)`.
- `OnClose()` – логирует отключение.
- `OnError(ErrorEventArgs e)` – логирует ошибки.

**Статические делегаты:**
- `_log` – для логирования в GUI.
- `_onTrail` – для передачи трека в `MainForm`.
- `_playSoundAction` – для воспроизведения звуков через GUI.

**Инициализация:** в `StartWebSocketSaveServer()` устанавливаются делегаты и запускается сервер.

---

#### 2.1.2. HTTP-сервер для триггера и списка треков (порт 8083)

**Класс:** `MainForm` (метод `ProcessTriggerRequest`)

**Назначение:** обслуживает GET-запросы от веб-карты:
- `/check_trigger?file=save_trail.trigger` – возвращает `{"exists": true/false}`.
- `/delete_trigger?file=save_trail.trigger` – удаляет файл.
- `/list_tracks` – возвращает список имён JSON-файлов в `saved_tracks`.
- `/get_track/{filename}` – возвращает содержимое JSON-файла.

**CORS:** добавлены заголовки `Access-Control-Allow-Origin: *`.

---

#### 2.1.3. Python-сервер (порт 8082)

**Назначение:** отдаёт статические файлы (HTML, CSS, JS, GeoJSON) из папки `data`. Запускается командой `python -m http.server 8082`.

**Используется для:** загрузки веб-карты, плеера и других ассетов.

---

### 2.2. Веб-карта (`web_pda_map.html`)

**Назначение:** отображение текущей позиции грузовика, маршрута, целей, сбор трека, сохранение через WebSocket.

**Основные переменные:**
- `state` – глобальный объект с данными: позиция, цель, города, дороги, шлейф, маркеры событий, топливо, урон и т.д.
- `saveWs` – WebSocket-клиент для сохранения треков (порт 8084).
- `socket` – WebSocket-клиент для телеметрии TruckTel (порт 8080).
- `wsConnected` – флаг подключения к телеметрии.
- `saveWsConnected` – флаг подключения к серверу сохранения.

**Ключевые функции:**
- `loadData()` – загружает города, дороги, POI, customTargets.
- `connectWebSocket()` – подключается к TruckTel (порт 8080) и обрабатывает телеметрию.
- `connectSaveWebSocket()` – подключается к серверу сохранения (порт 8084).
- `updateTrail(speed, pos, engineOn, fuel, damage, gameTime, heading)` – обновляет шлейф и события, добавляет точки с интервалом `TRAIL_INTERVAL` (3 м) и данные с интервалом `DATA_INTERVAL` (25 м).
- `saveTrail()` – отправляет собранный трек через `saveWs` и ждёт подтверждения.
- `resetTrail()` – сбрасывает шлейф и начинает новый.
- `drawMinimap()` – отрисовывает карту, шлейф, иконки, названия целей и городов.
- `greedyPlacement()` – расставляет текстовые метки без наложений.
- `playSoundViaWS(soundType)` – отправляет команду `play_sound` на сервер сохранения.

**Формат данных шлейфа:**
- Каждая точка: `{ p: "x z h", s: speed, t: elapsedSeconds }`
- `p` – строка с координатами и heading, разделёнными пробелами.
- `s` – скорость в км/ч (2 знака после запятой).
- `t` – время в секундах от начала записи (1 десятичный знак).

**Формат данных топлива/урона:** `{ p: "x z h", fuel: fuel, damage: wearPercent, t: elapsedSeconds }`

**Периодическая проверка триггера:** каждые 3 секунды отправляется GET-запрос на `http://localhost:8083/check_trigger`. При наличии файла вызывается `saveTrail()`, затем файл удаляется.

---

### 2.3. HTML-плеер (`track_*.html`)

**Назначение:** воспроизведение сохранённого трека с картой, шлейфом, событиями, данными.

**Генерируется** методом `GenerateTrailHtml` в `MainForm.cs`.

**Логика воспроизведения:**
- Использует время `t` из каждой точки для точного воспроизведения пауз и скоростей.
- При нажатии Play – рассчитывает прогресс по времени и перемещает грузовик.
- Ползунок `timeSlider` позволяет вручную перемещаться по треку.
- Карта поддерживает зум колесиком и перетаскивание (инвертированное).
- Отображает топливо и повреждения из `dataPoints` в панели.
- Отображает цели (активные и неактивные) и ближайшие города.

**Ключевые функции в плеере:**
- `parsePoint(p)` – разбирает строку `p` в объект `{x, z, h}`.
- `drawMap()` – полная отрисовка карты с дорогами, городами, целями, шлейфом, событиями, грузовиком и подписями.
- `fitMap()` – автоматически подбирает масштаб и центр по треку.
- `setTime(value)` – перемещает грузовик на указанную долю времени.
- `playStep()` – анимация воспроизведения с использованием `requestAnimationFrame`.

## 3. Взаимодействие через WebSocket

| Порт | Назначение | Клиент | Сервер |
|------|------------|--------|--------|
| 8080 | Телеметрия TruckTel | `web_pda_map.html` | ets2-telemetry-server (плагин игры) |
| 8084 | Сохранение треков | `web_pda_map.html` (saveWs) | GUI (`TrailBehavior`) |
| 8083 | HTTP-запросы (триггер, список) | `web_pda_map.html` (fetch) | GUI (HttpListener) |
| 8082 | Статика (HTML, CSS, GeoJSON) | Браузер | Python HTTP-сервер |

**Форматы команд WebSocket (порт 8084):**
- От клиента:
  - `{ "command": "play_sound", "type": "success" }` – воспроизвести звук success.
  - `{ ... трек JSON ... }` – передача трека.
- От сервера:
  - `{ "status": "ok", "message": "..." }` – подтверждение получения.

## 4. Ключевые константы и параметры

| Имя | Значение | Описание |
|-----|----------|----------|
| `TRAIL_INTERVAL` | 3 м | Минимальное расстояние между точками шлейфа |
| `DATA_INTERVAL` | 25 м | Интервал для записи данных (топливо, урон) |
| `NEARBY_CITIES_COUNT` | 4 | Количество ближайших городов для отображения |
| `MAX_SPEED_KMH` | 115 | Максимальная скорость для масштабирования |
| `LABEL_PADDING` | -5 | Плотность расстановки меток (greedy placement) |
| `ZOOM_MIN`/`ZOOM_MAX` | 0.5 / 4.8 | Минимальный и максимальный зум карты |

---

## 5. Важные замечания для доработок

- **Звуки** передаются через WebSocket (команда `play_sound`), чтобы обойти ограничения браузера (автовоспроизведение). Звуки реализованы в GUI через `System.Media.SystemSounds`.
- **Треки сохраняются** в папку `data/saved_tracks/` с двумя файлами: JSON и HTML.
- **Плеер** является самодостаточным (все данные встроены в JavaScript), не требует внешних ресурсов кроме CSS.
- **Данные телеметрии** берутся из WebSocket-потока TruckTel. Структура соответствует `truck.world.placement`, `truck.speed`, `truck.fuel`, `truck.wear` и т.д.
- **Износ (wear)** суммируется как сумма всех компонентов (`engine`, `transmission`, `cabin`, `chassis`, `wheels`) и сохраняется как «повреждения».

## 6. Расшифровка ключевых полей в JSON трека

```json
{
  "startTime": "ISO-время старта",
  "finishTime": "ISO-время финиша",
  "trail": [
    { "p": "x z heading", "s": "speed", "t": "elapsedSeconds" }
  ],
  "dataPoints": [
    { "p": "x z heading", "fuel": "fuel", "damage": "wear%", "t": "elapsedSeconds" }
  ],
  "events": [
    { "x": num, "z": num, "type": string, "label": string, "color": string, "subtext": string }
  ],
  "markers": [
    { "x": num, "z": num, "label": string, "color": string }
  ],
  "totalDistance": num,
  "mapData": {
    "cities": [ { "x": num, "z": num, "name": string } ],
    "roads": [ { "x1": num, "z1": num, "x2": num, "z2": num, "type": string } ]
  },
  "customTargets": [ { "x": num, "y": num, "z": num, "name": string, "active": bool, "color": string } ]
}
```

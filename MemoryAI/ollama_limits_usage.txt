# ollama_limits_usage.txt — учёт расхода лимитов ollama (Session usage)

Правила (см. MemoryAI/INSTRUCTIONS.md):
- ПЕРЕД НАЧАЛОМ любой задачи ВСЕГДА создавать план TODO (manage_todo_list).
- Первым пунктом TODO — оценка лимитов и прогноз (формат «Текущий ресурс: NN.N% RESET hh. Прогноз по завершении: ~NN% через ~hh.мин»), и только затем пункты задач.
- Проверять лимиты ПЕРЕД любой задачей (первый пункт TODO) и ПОСЛЕ всех задач.
- В долгих задачах — каждые ~5 минут; предупреждать пользователя о пороге 90% и 95%.
- После задачи записывать сюда: затраченные % и время.
- ВЫВОД: `SESSION: NN.N | RESET: <время до сброса>` (напр. "45 minutes").
- RESET учитывать в прогнозе: если до сброса мало времени, а задача большая —
  выгоднее дождаться сброса (лимиты обнулятся), чем рисковать прерваться на середине.
- Раз в день (перед началом работ) — перечитывать и обновлять РАЗДЕЛ 1.

====================================================================
МОДЕЛИ АГЕНТА (3 сценария, 01.09.2026)
====================================================================
Агент фиксирует своё имя (модель) в каждой записи лога (РАЗДЕЛ 2).
Используем 3 модели для 3 сценариев:
  1) Нормальная работа  -> glm5.3-flash:cloud
  2) Экономный режим    -> deepseek-v4-flash:cloud
  3) Макс. экономия     -> gemma4:cloud

Рекомендация модели по остатку ресурсов и времени до сброса (RESET):
- Остаток > 60% и RESET большой  -> glm5.3-flash:cloud (нормальная работа)
- Остаток 30-60% или RESET мал    -> deepseek-v4-flash:cloud (экономный)
- Остаток < 30% или RESET критичен -> gemma4:cloud (макс. экономия)
Правило: если задача большая, а до RESET мало времени — дождаться сброса
(лимиты обнулятся), затем работать на glm5.3-flash:cloud.

РАЗДЕЛ 1. Ресурсозатратность типовых задач (примерные оценки, % лимита)
====================================================================
Оценки на основе опыта сессий 31.08-01.09.2026. Уточняются по логу ниже.
Порог предупреждения: 90%. Порог жёсткой остановки: 95-97%.
Оценки даны для НОРМАЛЬНОЙ модели (glm5.3-flash:cloud); экономные модели
(deepseek-v4-flash, gemma4) тратят меньше (примерно x0.5-0.7).

- Простая правка JS (1-2 файла) + node --check + публикация:        ~2-4%
- Средний фикс бага (1 файл C#/JS + сборка + публикация):           ~4-8%
- Крупная задача (несколько файлов, итерации, отладка по логам):    ~8-15%
- Новая фича (рендер/канал/UI, несколько итераций + тест):          ~15-25%
- Полная сессия разработки (несколько задач подряд):                ~80-90%
- Публикация + синх бейджей (без правок кода):                      ~1-2%
- Диагностика по логам (без правок):                                ~1-3%

Правило прогноза: перед задачей оценить её класс, прибавить запас
(итерации/отладка), и если сумма с текущим % > 90 — предупредить
пользователя и предложить отложить/разбить задачу. Учесть модель
(экономные тратят меньше) и RESET (время до сброса).

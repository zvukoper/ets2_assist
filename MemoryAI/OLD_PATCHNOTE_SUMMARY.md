﻿# OLD_PATCHNOTE_SUMMARY

Краткая историческая сводка старых патчноутов/служебных записок проекта ETS2 Assist. Этот файл предназначен для быстрого восстановления контекста агентом. Описанные ниже решения относятся к историческим версиям и не заменяют актуальный код, `INSTRUCTIONS.md`, `CURRENT_TASK.md` и текущие логи.

## Область сводки

Сводка собрана из старых файлов в корне проекта: `BUILD_1.0.15_NOTES.md`, `VERSION_FIX.md`, `PATCH_INSTRUCTIONS.md`, `PATCH_1.0.20_NOTES.md`, `PATCH_1.0.21_NOTES.md`, `PATCH_1.0.22_NOTES.md`, `PATCH_1.0.23_NOTES.md`, `WEB_RUNTIME_SYNC_1.0.24.md`, `FULL_SYNC_1.0.25.md`, `FULL_REFRESH_1.0.26.md`, `FULL_REFRESH_1.0.27.md`, `PATCH_1.0.29_NOTES.md`, `SPLASH_REGRESSION_FIX_1.0.29.md`, `RELEASE_NOTES_1.0.30.md`, `RELEASE_NOTES_1.0.31.md`, `RELEASE_NOTES_1.0.32.md`, `MIGRATION_2026-08-25.md`, `SPLASH_FOCUS_FIX_2026-08-25.md`, `PUBLISH_DATA_RULE.md`, а также двух исторических заметок `MINIMAP_ARCHITECTURE_1.0.18.md` и `MINIMAP_ARCHITECTURE_1.0.19.md`.

**`АРХИТЕКТУРА ПРОЕКТА.md` не изменялся и в эту сводку не используется как объект редактирования.**

## Хронология и ключевые решения

### 1.0.15–1.0.19: базовая стабилизация карты

- Зафиксирован основной runtime-путь статических данных: `bin\Release\net10.0-windows\win-x64\publish\data`.
- Исправлен рендер миникарты: проверка ключа рендера выполняется до очистки canvas; дороги батчатся и кулируются.
- Сохранение/загрузка целей защищено от гонки между отложенной записью и чтением.
- Статические дороги, города и POI компилируются один раз в кэш `Path2D`; телеметрия меняет только динамический слой.
- Динамический слой включает грузовик, маршрут, цели, события, сетку и конус направления взгляда.
- Удалена дублирующая диагностическая панель; оставлена одна панель внутри/внизу справа миникарты.
- Для миникарты зафиксирована ориентация SCS/TruckTel: `0` = вперёд/север, `0.25` = влево, `0.5` = назад, `0.75` = вправо.

### 1.0.20: динамическая телеметрия и запись треков

- Dynamic state обновляется на каждом TruckTel delta frame.
- `processUpdate` переведён на `state.truck`, чтобы не использовать устаревшие DOM-значения.
- Запись трека расширена: руль, газ, тормоз, оси ввода, свет, `headOffset`, повреждение груза и другие состояния.
- `Shift+Ctrl+S` отправляет `save_trail` напрямую по существующему WS; trigger остаётся fallback.
- Добавлена защита от перезагрузки `custom_targets`, которая могла затирать случайную цель.
- Кадр записи создаётся сразу при изменении значимых органов управления/света/головы, а не только по дистанции.
- Для событий/дистанционных маркеров исправлен фон и читаемость.

### 1.0.21: разделение статического и динамического рендера

- Размер canvas меняется только при реальном resize; поток телеметрии больше не сбрасывает буферы.
- Добавлен отдельный heartbeat рендера 50 мс, независимый от частоты WS.
- Статический слой и динамический слой перерисовываются раздельно.
- POI берутся из верхнеуровневых массивов `Overlays.json`, включая пустые категории.
- Цвет POI определяется корневой категорией.
- Для WebSocket-клиента добавлена доставка текущей команды видимости UI, чтобы Hybrid не пропускал начальный `show_ui_first`.
- Сохранение трека по WS защищено lock-механизмом; trigger используется только как запасной путь.

### 1.0.22–1.0.24: борьба с устаревшими web-ресурсами

- Python static server заменён на локальный `HttpListener`.
- Сервер отдаёт no-cache заголовки и сохраняет стабильные URL WebOverlay.
- Все верхнеуровневые массивы `Overlays.json` считаются категориями POI и логируются.
- Основная проблема этих версий: desktop EXE и web-runtime могли расходиться по версии.
- С 1.0.23 при старте создаётся один Unix epoch token, а локальные JS/CSS получают `?t=<epoch>`; старые `?v=` заменяются.
- В логах печатаются fingerprint/метаданные фактически обслуживаемых `web_pda_map.html` и `web_ui_hybrid.html`.
- 1.0.24 синхронизировал исходники publish-time web runtime с MainForm/BuildInfo; стабильные URL сохранялись.

### 1.0.25–1.0.27: полные refresh/sync без уничтожения пользовательских данных

- Полные обновления должны оставлять пользовательские и статические данные на месте.
- Сохраняемые данные: GeoJson, `Overlays.json`, `localized_cities`, `config.json`, `custom_targets.json`, `job_state.json`, `ws_config.json`, `web_data.json`, `saved_tracks`, Logs и другой runtime state — в зависимости от версии/пакета.
- Уточнён принцип: менять приложение/web-runtime отдельно от больших статических наборов карты.
- 1.0.27 продолжил обработку всех TruckTel delta frames и прямого `save_trail`.
- Hybrid должен обновлять speed/fuel/engine на каждом delta.
- Введён автоматический поиск/восстановление отсутствующих статических файлов из legacy `data`, если это возможно.

### 1.0.29: откат регрессии Splash и исправление карты

- Восстановлена ранее проверенная реализация Splash: bitmap/form/display `314x314`, DPI `96`, без лишнего внутреннего padding.
- Process-wide DPI override признан причиной регрессии; DPI-контекст перенесён в сам SplashForm (`PerMonitorV2`).
- `UpdateLayeredWindow` должен использовать физический размер bitmap.
- В 1.0.28 map WS callback ссылался на отсутствующую `applyTelemetryDelta()`; исправлено на `mergeTelemetryData(data, "delta")`.
- Визуально Hybrid build badge сделан белым с тонкой чёрной обводкой.

### 1.0.30–1.0.32: playback, static data и AppData

- Playback получил рабочий `drawMap()` и больше не должен падать на `ReferenceError`.
- Сохранённые треки перестали встраивать огромные массивы roads/cities в save payload там, где использовались статические ресурсы.
- Затем playback был переведён на локальный HTML и встроенный статический snapshot из `.map.json`/HTML, чтобы воспроизведение не зависело от GeoJson/Overlays.
- Запись snapshot включает города, дороги, POI, категории/счётчики и custom targets.
- Save hotkey: пауза через SCS SDK → ожидание подтверждённой паузы → запрос сохранения; автоматический unpause не выполняется.
- Появилась кнопка сброса начала записи без уничтожения накопленного трека.
- Нормализация live telemetry закрепила TruckTel flat keys для speed/engine/fuel/rest/steering/throttle/brake/odometer/head offset/wear/trailer/lights.
- HTTP polling Hybrid больше не должен затирать валидные WS-значения нулями/дефолтами.
- Добавлен brake indicator; сохранены trailer/lights indicators.
- Добавлен head-view cone в live minimap и playback; затем исправлялось вертикальное отображение marker playback.
- Static map loader получил localhost fallback и retry.
- В 1.0.32 статические web/map ресурсы стали частью корневого `data` и автоматически копируются при `dotnet publish`.
- Пользовательские настройки, custom targets, telemetry cache, triggers и saved tracks вынесены в `%LOCALAPPDATA%\ETS2_Assist`.

### Миграция 2026-08-25

- `Ets2Telemetry.exe` больше не должен запускаться из ETS2 Assist.
- `ets2-telemetry-server.dll` перестал быть обязательным; допускается `trucktel.dll` как telemetry provider во время миграции.
- Исторически pause API был `http://localhost:8080/api/rest/single/frame/paused`; это относится к миграционному состоянию и не следует считать вечным номером порта.
- После случайной цели игра должна оставаться на паузе; автоматический unpause был удалён.
- Повторный переход в pause не должен происходить, если цель уже достигнута внутри установленной паузы.
- Splash переведён на `WS_EX_LAYERED` + `UpdateLayeredWindow`; `TransparencyKey` для Splash был исключён.
- Сохранение треков переведено на request/response correlation через `requestId`.
- Финальная проверка исторически требовала отдельной проверки на Windows.

### Splash/focus fix 2026-08-25

- Диалоги завершения квестов сделаны отдельными модальными WinForms HWND.
- Для возврата фокуса применялись `AttachThreadInput`, `SetForegroundWindow`, `SetActiveWindow`, `SetFocus`.
- После закрытия финального диалога foreground возвращался к `eurotrucks2.exe`.
- Splash продолжал использовать PerMonitorV2, без WinForms autoscaling, с физическим размером PNG для `UpdateLayeredWindow`.

### Правила публикации

- Исходный `data` в репозитории считается authoritative source.
- `dotnet publish -c Release` создаёт runtime-копию `publish\data`; generated publish directory не должна считаться исходником.
- Mutable user data хранится вне install dir, в `%LOCALAPPDATA%\ETS2_Assist`.
- После изменения статических ресурсов необходимо снова выполнять publish.

## Что считать полезным при будущей диагностике

1. Если desktop build и web UI расходятся по версиям — сначала сравнивать source `data` и фактический `publish\data`, затем проверять cache-busting/no-cache и fingerprint в логах.
2. Для карты не возвращать разбор больших GeoJson/Overlays на каждый telemetry frame: статические данные должны жить в кэше, динамика — обновляться отдельно.
3. При проблемах Splash сначала проверять PerMonitorV2/физический размер bitmap, а не добавлять новые process-wide DPI overrides.
4. При работе с пользовательскими данными не заменять GeoJson/Overlays/config/saved_tracks без явной необходимости.
5. Исторический порт `8080` не считать гарантированным: современные логи могут показывать динамически обнаруженный TruckTel-порт.

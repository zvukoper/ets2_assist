# ЗАДАЧА: заменить COLORKEY/DITHER AR overlay на настоящий per-pixel alpha через DirectComposition

## 1. Цель

Изменить AR overlay в репозитории `zvukoper/ets2_assist` так, чтобы прозрачность каждого пикселя передавалась Windows как настоящий alpha.

Требования результата:

* убрать `LWA_COLORKEY`;
* убрать Bayer/dither alpha;
* убрать зависимость прозрачности от чёрного цвета;
* сохранить D3D11 renderer;
* сохранить click-through;
* сохранить topmost/no-activate;
* сохранить существующую логику проекции и геометрии;
* добиться корректной прозрачности `0..1` для кругов, боксов, плоскостей, линий, куба, эллипсов и теней;
* использовать DirectComposition;
* использовать composition swap chain;
* использовать premultiplied alpha;
* не менять текущую AR-математику и source данных без необходимости.

---

# 2. Диагностика текущей реализации

Текущий `AR/ArOverlayWindow.cs` создаёт окно с:

```csharp
WS_EX_LAYERED |
WS_EX_TRANSPARENT |
WS_EX_TOPMOST |
WS_EX_NOACTIVATE |
WS_EX_TOOLWINDOW
```

после чего устанавливает:

```csharp
SetLayeredWindowAttributes(hwnd, 0x000000, 0, LWA_COLORKEY);
```

То есть окно работает в режиме color key: чёрный цвет используется как прозрачный.

Текущий `AR/ArRenderer.cs` создаёт swap chain через:

```csharp
CreateSwapChainForHwnd(...)
```

с конфигурацией:

```csharp
SwapEffect = SwapEffect.Sequential
AlphaMode = AlphaMode.Ignore
```

Это соответствует текущей COLORKEY-схеме, но не даёт композиции per-pixel alpha.

Текущий shader куба содержит Bayer-dither:

```hlsl
if (a >= bayer[idx])
    return float4(i.col.rgb, 1.0f);

return float4(0, 0, 0, 1.0f);
```

при котором alpha преобразуется в пространственную шахматную маску. Чёрный результат затем интерпретируется COLORKEY как прозрачный.

Это удалить полностью.

---

# 3. Целевая архитектура

Использовать следующую схему:

```text
D3D11 device
    ↓
IDXGIFactory2
    ↓
CreateSwapChainForComposition
    ↓
DXGI_FORMAT_B8G8R8A8_UNORM
DXGI_ALPHA_MODE_PREMULTIPLIED
DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL
    ↓
IDCompositionDevice
    ↓
IDCompositionTarget::CreateTargetForHwnd
    ↓
IDCompositionVisual
    ↓
Visual::SetContent(swapChain)
    ↓
Target::SetRoot(visual)
    ↓
DCompDevice::Commit()
```

`CreateSwapChainForComposition` предназначен именно для передачи Direct3D content в DirectComposition и требует flip model.

Microsoft также описывает связку D3D11 + DXGI composition swap chain + premultiplied alpha + DirectComposition как штатный способ высокопроизводительной per-pixel прозрачности.

# 5. Изменения в ArRenderer.cs: swap chain

## 5.1. Тип swap chain

Оставить:

```csharp
IDXGISwapChain1
```

но создавать его не через:

```csharp
CreateSwapChainForHwnd
```

а через:

```csharp
CreateSwapChainForComposition
```

---

## 5.2. Конфигурация swap chain

Использовать:

```csharp
var sc = new SwapChainDescription1
{
    Width = (uint)width,
    Height = (uint)height,

    Format = Format.B8G8R8A8_UNorm,

    Stereo = false,

    SampleDescription = new SampleDescription(1, 0),

    BufferUsage = Usage.RenderTargetOutput,

    BufferCount = 2,

    Scaling = Scaling.Stretch,

    SwapEffect = SwapEffect.FlipSequential,

    AlphaMode = AlphaMode.Premultiplied,

    Flags = SwapChainFlags.None
};
```

Не использовать:

```csharp
SwapEffect.Sequential
AlphaMode.Ignore
CreateSwapChainForHwnd
```

для нового прозрачного пути.

Для flip-model swap chain `B8G8R8A8_UNORM` допустим, MSAA не используется, `BufferCount` должен быть 2..16.

Для composition swap chain `SwapEffect = FlipSequential` обязателен.

`AlphaMode.Premultiplied` должен означать реальную premultiplied-alpha поверхность. DXGI определяет этот режим как поверхность, в которой RGB уже масштабированы alpha.

# 6. DirectComposition initialization

Добавить в `ArRenderer` или отдельный composition helper поля:

```csharp

private IDCompositionTarget? _dcompTarget;
private IDCompositionVisual? _dcompVisual;
```

Получить `IDXGIDevice` из `ID3D11Device`.

Концептуально:

```csharp
using IDXGIDevice dxgiDevice = _device.QueryInterface<IDXGIDevice>();
_dcompDevice = DCompositionCreateDevice(dxgiDevice);
```

Использовать соответствующий API Vortice для установленной версии пакетов проекта. Не придумывать типы/методы; сначала проверить реальную версию `Vortice.Windows` и существующие binding API в проекте.

Microsoft sequence:

1. получить `IDXGIDevice` из D3D11 device;
2. создать DirectComposition device через `DCompositionCreateDevice`;
3. создать target для HWND;
4. создать visual;
5. установить swap chain как content visual;
6. назначить visual root target;
7. выполнить `Commit`.

# 11. Альфа-схема: использовать premultiplied alpha

Выбрать один из двух допустимых вариантов и реализовать его последовательно:

### Вариант A: shader самостоятельно premultiply

Shader получает:

```text
RGB = обычный цвет
A   = alpha
```

и возвращает:

```hlsl
return float4(color.rgb * alpha, alpha);
```

Тогда BlendState:

```text
SourceBlend = ONE
DestinationBlend = INVERSE_SOURCE_ALPHA
```

Это рекомендуемый вариант для единообразия всех shader pipelines.

### Вариант B: shader возвращает straight alpha, а blend state выполняет premultiplication

В этом случае shader возвращает:

```hlsl
float4(color.rgb, alpha)
```

а BlendState должен использовать:

```text
SourceBlend = SOURCE_ALPHA
DestinationBlend = INVERSE_SOURCE_ALPHA
```

Microsoft прямо отмечает, что premultiplication может выполняться на output-merger через `SrcBlend = SRC_ALPHA`.

Для проекта выбрать **вариант A** и не смешивать A/B между pipeline.

# 12. Рекомендуемый BlendState для проекта

Для варианта A использовать:

```csharp
var bd = new BlendDescription
{
    AlphaToCoverageEnable = false,
    IndependentBlendEnable = false
};

bd.RenderTarget[0] = new RenderTargetBlendDescription
{
    BlendEnable = true,

    SourceBlend = Blend.One,
    DestinationBlend = Blend.InverseSourceAlpha,

    BlendOperation = BlendOperation.Add,

    SourceBlendAlpha = Blend.One,
    DestinationBlendAlpha = Blend.InverseSourceAlpha,

    BlendOperationAlpha = BlendOperation.Add,

    RenderTargetWriteMask = ColorWriteEnable.All
};
```

Критическое правило:

```text
Shader RGB already premultiplied
+
SourceBlend = ONE
```

Не делать premultiply дважды.

# 14. Pixel shader markers

Для маркера использовать нормальный per-pixel alpha:

```hlsl
float4 PMain(VS_OUT i) : SV_TARGET
{
    float dpx = distance(i.px, Circle.xy);
    float R = Circle.z;

    float body =
        smoothstep(R + 0.5, R - 1.0, dpx);

    float ring =
        smoothstep(R - 3.5, R - 2.5, dpx) *
        smoothstep(R + 0.5, R - 1.0, dpx);

    float3 color =
        lerp(Tint.rgb, float3(0, 0, 0), ring);

    float alpha =
        saturate(Circle.w * (body + ring * 0.6));

    return float4(color * alpha, alpha);
}
```

Не преобразовывать alpha в бинарное состояние.

Допускаются `smoothstep`, distance-based falloff, anti-aliasing и другие непрерывные alpha-функции.

# 18. Soft shadow

Сделать тень как реальную alpha gradient.

Использовать непрерывную функцию falloff.

Пример:

```hlsl
float ShadowFalloff(float d)
{
    d = saturate(d);

    float a = 1.0 - smoothstep(0.0, 1.0, d);

    return a * a;
}
```

Затем:

```hlsl
float shadow = ShadowFalloff(d);
float alpha = shadow * Tint.a;

return float4(Tint.rgb * alpha, alpha);
```

Для тени предпочтителен второй порядок falloff (`a * a`) либо аналогичная плавная функция.

Не использовать dither.

# 28. Важный нюанс: WS_EX_NOREDIRECTIONBITMAP

Использовать:

```csharp

```

как часть intended DirectComposition window path.

Не считать его обязательным именно потому, что существует DirectComposition API, но проверить его наличие при создании окна.

Microsoft examples используют этот стиль для окон, поверхность которых должна формироваться DirectComposition без стандартной redirection bitmap.

Если конкретный runtime проекта показывает проблему с этим стилем, экспериментально сравнить:

```text
WS_EX_NOREDIRECTIONBITMAP + DComp
```

и:

```text
обычное WS_POPUP + DComp
```

но COLORKEY не возвращать.

# 33. Web/референсная проверка

Ориентироваться на следующие подтверждённые реализации:

1. Microsoft DirectComposition documentation:
   `CreateSwapChainForComposition` предназначен для передачи D3D content в DirectComposition; для него нужен flip model.

2. Microsoft documentation:
   `DXGI_ALPHA_MODE_PREMULTIPLIED` означает, что RGB уже умножены на alpha.

3. Microsoft DirectComposition transparency example:
   использует composition swap chain и premultiplied alpha для per-pixel transparency.

4. Microsoft Q&A example:
   практически совпадает с требуемой схемой:
   `WS_EX_NOREDIRECTIONBITMAP`
   +
   `CreateSwapChainForComposition`
   +
   `FlipSequential`
   +
   `Premultiplied`
   +
   `CreateTargetForHwnd`
   +
   `SetContent(swapchain)`.

5. Реальный open-source game overlay `procmod-overlay` реализует прозрачный click-through D3D11 overlay как отдельное окно поверх игры, что подтверждает практичность этой архитектуры для game overlays.

# 34. Критические ошибки, которых нельзя допустить

## Ошибка 1

Использовать одновременно:

```text
Premultiplied swap chain
+
straight RGB
+
SourceBlend = ONE
```

Это даст неправильные яркости.

---

## Ошибка 2

Дважды premultiply:

```text
shader: RGB *= A
+
blend: SourceBlend = SRC_ALPHA
```

Это уменьшит RGB лишний раз.

---

## Ошибка 3

Оставить COLORKEY.

После перехода на DirectComposition:

```text
SetLayeredWindowAttributes
LWA_COLORKEY
```

должны исчезнуть.

---

## Ошибка 4

Оставить Bayer-dither как "оптимизацию".

Dither больше не нужен.

---

## Ошибка 5

Оставить:

```text
AlphaMode.Ignore
```

Это отключает использование alpha как transparency metadata.

---

## Ошибка 6

Создать:

```text
CreateSwapChainForComposition
+
SwapEffect.Sequential
```

Это неверно. Composition swap chain требует flip model.

---

## Ошибка 7

Использовать CPU bitmap/GDI промежуточным слоем.

Это нарушит требуемую D3D11 → compositor архитектуру.

---

# 35. Финальная целевая конфигурация

```text
Window:
    WS_EX_NOREDIRECTIONBITMAP
    WS_EX_TRANSPARENT
    WS_EX_TOPMOST
    WS_EX_NOACTIVATE
    WS_EX_TOOLWINDOW
    WS_POPUP

SwapChain:
    Format = B8G8R8A8_UNORM
    Sample = 1
    BufferCount = 2
    Scaling = Stretch
    SwapEffect = FlipSequential
    AlphaMode = Premultiplied

Rendering:
    Clear = (0,0,0,0)
    Shader output = premultiplied RGBA
    Blend:
        Src = ONE
        Dst = ONE_MINUS_SRC_ALPHA

Composition:
    D3D11 Device
      ↓
    IDXGIDevice
      ↓
    IDCompositionDevice
      ↓
    IDCompositionTarget
      ↓
    IDCompositionVisual
      ↓
    SwapChain
      ↓
    Commit

Forbidden:
    LWA_COLORKEY
    COLORKEY
    Bayer
    alpha thresholding
    black-as-transparent
    GDI copy
    CPU bitmap compositing
```

# 36. Definition of Done

Задача считается выполненной только если:

```text
1. Проект собирается.
2. AR запускается.
3. ETS2 полностью видна через пустые области overlay.
4. alpha=1 даёт непрозрачный объект.
5. alpha=0.5 даёт реальную полупрозрачность.
6. alpha=0.1 даёт равномерную слабую прозрачность.
7. отсутствует Bayer pattern.
8. отсутствует COLORKEY.
9. отсутствуют чёрные ореолы.
10. soft shadow имеет плавный градиент.
11. click-through работает.
12. topmost работает.
13. render thread сохраняет текущую модель.
14. существующая проекция AR не изменена.
15. нет CPU/GDI compositing.
16. DirectComposition используется как реальный compositor path.
17. resize не ломает rendering.
18. dispose не вызывает use-after-free.
19. ошибки DirectComposition/DXGI логируются.
20. в коде не осталось комментариев, описывающих старую COLORKEY/DITHER архитектуру как рабочую.
```

# Задача: CABIN/OTHER + FOV-компенсация AR

## 1. Определение режима CABIN / OTHER

Цель:
По изображению полноэкранного ETS2 определить, находится ли игрок в стандартной внутренней камере кабины.

Не использовать FOV для классификации.

### CABIN-признаки

Кадр считать `CABIN`, если одновременно выполняются основные условия:

1. В нижней части изображения присутствуют элементы интерьера кабины:

   * приборная панель;
   * руль;
   * элементы торпедо;
   * стойки/рама кабины;
   * зеркала или другие фиксированные элементы интерьера.

2. Геометрия изображения соответствует виду из кабины:

   * крупные элементы интерьера находятся на переднем плане;
   * дорожная сцена находится за пределами кабины;
   * отсутствует внешний вид грузовика целиком.

3. Интерьер должен сохраняться между соседними кадрами:

   * не переключать режим из-за одного ошибочного кадра;
   * использовать временную стабилизацию состояния.

### OTHER-признаки

`OTHER`, если:

* интерьер кабины отсутствует;
* явно наблюдается внешняя камера;
* изображение соответствует другой игровой камере;
* уверенность классификатора ниже порога.

### Реализация

Сделать отдельный компонент:

`CameraModeDetector`

Результат:

```csharp
enum CameraMode
{
    Unknown,
    Cabin,
    Other
}
```

Использовать confidence:

```csharp
record CameraModeResult(
    CameraMode Mode,
    float Confidence);
```

Требование:
состояние `CABIN` и `OTHER` не должно переключаться от единичного неуверенного кадра.

Использовать hysteresis / temporal voting.

Пример:

* для входа в `CABIN` необходимо несколько последовательных кадров;
* для выхода из `CABIN` также несколько подтверждений;
* при низкой уверенности сохранять предыдущее состояние.

Пороговые значения вынести в настройки.

---

# 2. FOV для AR

Для AR-преобразования считать базовым FOV:

```text
FOV = 65°
```

Использовать его только в режиме `CABIN`.

Не смешивать:

* FOV камеры ETS2;
* FOV внешней камеры;
* FOV debug/free camera;
* FOV multi-monitor.

`65°` считать конфигурационным параметром:

```csharp
double CabinFovDegrees = 65.0;
```

Не зашивать 65 непосредственно в формулы.

---

# 3. Главная проблема текущей реализации AR

Сейчас метки немного смещаются при повороте головы.

Причина, которую необходимо устранить:
координаты AR нельзя пересчитывать как простое линейное смещение от углов головы.

Использовать полноценную pinhole camera projection.

Проекция должна зависеть от:

```text
world/object position
+
camera position
+
camera rotation
+
FOV
+
screen aspect ratio
```

Алгоритм должен быть единым для всех кадров.

---

# 4. Проекция 3D точки на экран

Для каждой AR-точки иметь мировую позицию:

```text
Pworld
```

Позицию камеры:

```text
Cworld
```

и ориентацию камеры:

```text
Rcamera
```

Сначала преобразовать мировую точку в camera space:

```text
Pcamera = inverse(Rcamera) * (Pworld - Cworld)
```

Получить:

```text
x = Pcamera.X
y = Pcamera.Y
z = Pcamera.Z
```

Если используемая система координат проекта имеет другую ориентацию осей, привести её к единой camera-space системе перед projection.

Точка находится перед камерой только при положительном направлении depth согласно принятой системе координат.

---

# 5. Перспективная проекция

Для горизонтального FOV использовать:

```text
f = 1 / tan(FOV_horizontal / 2)
```

Для экрана:

```text
aspect = screenWidth / screenHeight
```

Вертикальный FOV вывести из aspect ratio:

```text
FOV_vertical =
    2 * atan(tan(FOV_horizontal / 2) / aspect)
```

Не использовать одинаковый FOV одновременно по X и Y.

Нормализованные координаты:

```text
ndcX = (cameraX / cameraZ) * f
ndcY = (cameraY / cameraZ) * f * aspect
```

После чего:

```text
screenX = (ndcX + 1) * 0.5 * screenWidth
screenY = (1 - ndcY) * 0.5 * screenHeight
```

Знак Y привести к используемой системе координат UI.

---

# 6. Устранение drift при повороте головы

Критически важно:

**Не рассчитывать положение метки относительно предыдущего положения метки.**

Каждый кадр выполнять полный пересчёт:

```text
World position
    ->
Current camera transform
    ->
Current camera-space position
    ->
Perspective projection
    ->
Screen position
```

То есть положение AR является функцией только текущего состояния:

```text
ScreenPosition =
    Project(
        WorldPosition,
        CurrentCameraPosition,
        CurrentCameraRotation,
        CabinFov,
        ScreenSize)
```

Не использовать:

```text
previousScreenPosition + deltaHeadRotation
```

и аналогичные накопительные схемы.

---

# 7. Обработка поворота головы

Если система получает yaw/pitch/roll головы:

1. Получить текущую ориентацию головы.
2. Преобразовать её в ориентацию игровой камеры.
3. Применить rotation к world-to-camera transform.
4. Выполнить projection.

Не выполнять отдельный эмпирический `X += yaw * coefficient`.

Связь между углом головы и положением метки должна возникать автоматически через перспективную проекцию.

---

# 8. Центр проекции

Не предполагать, что центр камеры автоматически совпадает с центром экрана.

Ввести параметры:

```text
ProjectionCenterX
ProjectionCenterY
```

По умолчанию:

```text
0.5
0.5
```

или:

```text
screenWidth / 2
screenHeight / 2
```

В дальнейшем параметры должны позволять компенсировать реальное смещение точки зрения ETS2 относительно центра viewport.

Итоговая формула должна поддерживать:

```text
screenX = projectionCenterX + projectedOffsetX
screenY = projectionCenterY + projectedOffsetY
```

---

# 9. FOV compensation

Сделать отдельный projection module:

```text
CabinArProjection
```

Он должен принимать:

```csharp
Project(
    Vector3 worldPosition,
    CameraPose cameraPose,
    float fovDegrees,
    int screenWidth,
    int screenHeight)
```

Не смешивать projection с:

* распознаванием CABIN/OTHER;
* получением данных WebSocket;
* UI rendering;
* логикой AR marker lifetime.

---

# 10. Проверка корректности

Создать диагностический режим.

Разместить несколько виртуальных точек:

```text
центр
лево
право
верх
низ
далеко
близко
```

Проверить движение камеры:

1. yaw влево;
2. yaw вправо;
3. pitch вверх;
4. pitch вниз;
5. возврат в исходное положение.

Критерий:
после возврата камеры в исходное состояние точка должна возвращаться в исходную экранную координату без накопившегося смещения.

Отдельно проверить:

* yaw ±10°;
* yaw ±20°;
* yaw ±30°;
* pitch ±10°;
* pitch ±20°.

---

# 11. Проверка FOV

Добавить debug overlay:

```text
CameraMode
FOV
CameraPosition
CameraYaw
CameraPitch
ProjectionCenter
ScreenPosition
```

Добавить возможность менять:

```text
CabinFovDegrees
```

без перекомпиляции либо через debug/config.

Проверить минимум:

```text
55°
60°
65°
70°
75°
80°
```

При правильном FOV неподвижная мировая точка должна оставаться привязанной к одной и той же мировой точке при движении головы.

---

# 12. Важное ограничение

Не считать, что проблема обязательно только в FOV.

Если после корректной pinhole projection при `65°` сохраняется постоянный drift при yaw, проверить:

1. неправильный порядок применения rotations;
2. перепутанные оси;
3. знак yaw/pitch;
4. неправильный pivot камеры;
5. различие между head rotation и game camera rotation;
6. смещение projection center;
7. неправильный aspect ratio;
8. несовпадение real camera FOV и используемого 65°.

Только после проверки этих пунктов вводить дополнительные эмпирические коэффициенты.

---

# 13. Архитектурный результат

Разделить систему на независимые компоненты:

```text
ScreenCapture
    ->
CameraModeDetector
    ->
CameraPose
    ->
CabinArProjection
    ->
AR Marker Renderer
```

При `OTHER`:

```text
AR cabin projection disabled
```

При `CABIN`:

```text
FOV = CabinFovDegrees
projection = CabinArProjection
```

Все параметры FOV и projection center должны быть конфигурационными.

Главный критерий готовности:

**AR-метка должна восприниматься как приклеенная к неподвижной точке пространства при yaw/pitch камеры, без бокового плавания и накопительного смещения.**

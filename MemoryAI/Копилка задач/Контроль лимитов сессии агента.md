# Контроль лимитов сессии агента (строгий режим)

Дата: 31.08.2026. Автор: пользователь. Из «Копилки задач» — возможно взять на постоянную основу.

## Правила (v1, эксперимент)

1. **Каждые ~10 минут** работы агента — замер Session usage (`ollama_usage_v2.bat`, источник https://ollama.com/settings).
2. **> 90%** — агент ОСТАНАВЛИВАЕТ выполнение новых задач и ПРЕДУПРЕЖДАЕТ пользователя
   (выводит процент + предлагает упростить/разбить задание).
3. **> 97%** — ПОЛНАЯ ПАУЗА:
   - сохранить контекст (`/memories/session/*`) и MemoryAI (INSTRUCTIONS/WORKLOG);
   - сгенерировать текст коммита (git commit message) по текущим изменениям;
   - корректно завершить сессию (не начинать новых правок).
4. Процент — первой задачей в TODO каждой сессии; прогрессбар — в резюме после публикации.

## Механика для агента
- Инструмент: `ollama_usage_v2.bat` → `SESSION: NN.N`.
- Таймер агент отслеживает сам (по времени последнего замера; перед КАЖДОЙ новой
  задачей/этапом — если прошло ≥10 мин — замерить заново).
- `SESSION: UNKNOWN` (сессия ollama истекла) — попросить перезапустить
  `ollama_login.bat`, процент считать критичным только по последнему известному.

## Идеи на будущее

- Отображение прогрессбара в статус-баре ETS2 Assist.
- Журнал расхода квоты по задачам (сколько % съедает типовая задача) для планирования.
